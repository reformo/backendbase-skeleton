01 / Context and file map

Keep one model inside its boundary

A bounded context owns its business terms, rules, contracts, and adapters. This guide follows the existing ExampleCatalog context.

The example creates a system Entry in group settings, with key page-size, value 25, and no target identifier.

The companion query reads the same Entry. Later changes update its value or mark it removed. Its HTTP resource name is example.

Reading key. “Current source excerpt” means copied implementation. “Illustrative example” means sample usage of existing APIs. No sample feature is installed by this guide.

Command Query Responsibility Segregation (CQRS) separates writes from reads. A port declares required behavior. An adapter implements that port with a specific technology.

Dependency injection (DI) supplies services and port implementations. Doctrine Object Relational Mapping (ORM) maps records. Its Database Abstraction Layer (DBAL) executes SQL queries.

SQL means Structured Query Language. UUID means universally unique identifier. UTC means Coordinated Universal Time.

An outbox stores events with business writes for later publication. An inbox records consumer processing to prevent repeated committed database work.

AreaResponsibilityDependency boundary
DomainEntry behavior, identity, validated values, and snapshots.No HTTP, Doctrine, queue, container, or application-handler dependency.
ContractsCommands, queries, repository ports, read models, and event contracts.Published context types. CQRS contracts do not import their handlers.
ApplicationHandle a use case. Call domain behavior and ports. Select transaction and event timing.No SQL, HTTP response construction, or concrete infrastructure adapter.
AdaptersMap aggregates and projections to database or memory storage.Context-owned persistence adapters stay beside their context.
InfrastructureImplement shared buses, event dispatch, transactions, queue delivery, and inbound APIs.Framework details remain outside the domain and application layers.

02 / Queries and handlers

Read through a declared result contract

When: Add a query when a caller needs data without a state change. Reuse a query only when its meaning and result match.

Where: Put the query in Contracts/Query. Put its result in Contracts/ReadModel and handler in Application/QueryHandlers.

How: Implement Query<TResult>. Declare the concrete handler result. Inject a read port. Register the contract-to-handler pair.

Current source excerpt: GetEntryByCriteriaHandler::handle(). Enclosing class and imports are omitted.

public function handle(Query $query): EntryDetails|null
{
    return $this->entryRepository->getEntryByCriteria($query);
}

Source: src/Backendbase/Domain/ExampleCatalog/Application/QueryHandlers/GetEntryByCriteriaHandler.php.

GetEntryByCriteria declares Query<EntryDetails|null>. It carries type, nullable target identifier, group, and key.

This query constructor stores those scalar criteria. It does not validate group, key, or target ranges. The caller must validate boundary input.

New inputs must follow the CQRS contract rules. Use typed values when they carry business rules.

Illustrative example. Uses existing APIs; it is not a new source file.

use Backendbase\Domain\ExampleCatalog\Contracts\Query\GetEntryByCriteria;
use Backendbase\Domain\ExampleCatalog\Domain\EntryType;

// $queryBus is an injected Backendbase\Shared\CQRS\QueryBus.
$query = new GetEntryByCriteria(EntryType::SYSTEM, null, 'settings', 'page-size');
$entryDetails = $queryBus->handle($query);
// $entryDetails is Contracts\ReadModel\EntryDetails|null.

03 / Commands and domain behavior

Change state through one use case

When: Add a command for an intended state change. Commands and command handlers return void.

Where: Put the command in Contracts/Command. Put the handler in Application/CommandHandlers. Keep invariants in Domain.

How: Implement Command. Carry only use-case data. Validate business values during construction. Inject ports or small application services into the handler.

AddEntry creates EntryIdentity, EntryId, EntryValue, and primitive EntryDetails. Invalid values fail before dispatch.

Illustrative example. Uses existing APIs; it is not a new source file.

use Backendbase\Domain\ExampleCatalog\Contracts\Command\AddEntry;
use Backendbase\Domain\ExampleCatalog\Domain\EntryType;
use Ramsey\Uuid\Uuid;

// $commandBus is an injected Backendbase\Shared\CQRS\CommandBus.
$entryId = Uuid::uuid7()->toString();
$command = new AddEntry(
    $entryId,
    EntryType::SYSTEM,
    null,
    'settings',
    true,
    'page-size',
    '25',
    ['unit' => 'items'],
);
$commandBus->handle($command);
// Use $entryId only after successful completion.

Current source excerpt: AddEntryHandler::handle(). Enclosing class and imports are omitted.

public function handle(Command $command): void
{
    $writes      = $this->writes;
    $transaction = $this->transaction;
    $work        = static fn () => $writes->add($command);
    $domainEvent = static fn (IntegrationEvent $event): EntryAdded => new EntryAdded($command, $event->occurredOn());
    $transaction->execute($work, $domainEvent);
}

Source: src/Backendbase/Domain/ExampleCatalog/Application/CommandHandlers/AddEntryHandler.php.

In this handler, EntryAdded refers to Contracts/DomainEvents/EntryAdded. The transaction callback returns a separate integration event.

Current source excerpt: EntryWrites::add(). Enclosing class and imports are omitted.

public function add(AddEntry $command): EntryAdded
{
    $clock        = $this->clock;
    $now          = $clock->now();
    $entryId      = $command->entryId();
    $type         = $command->type();
    $typeTargetId = $command->typeTargetId();
    $group        = $command->group();
    $isActive     = $command->isActive();
    $key          = $command->key();
    $value        = $command->value();
    $details      = $command->details();
    $entry        = Entry::create($entryId, $type, $typeTargetId, $group, $isActive, $key, $value, $details, $now);
    $repository   = $this->repository;
    $repository->add($entry);

    return new EntryAdded(new EntryAddedPayload($entryId, $type->value, $typeTargetId, $group, $isActive, $key, $value, $details), $now);
}

Source: src/Backendbase/Domain/ExampleCatalog/Application/EntryWrites.php.

Entry::create() validates the aggregate state. Entry::change() validates replacements before mutation. Entry::remove() records removal time.

EntryWrites owns the application sequence. It reads the injected UTC clock inside transactional work and passes one instant to creation and related events.

For change and removal, it first resolves current state through the write repository. It reads the clock after that lookup.

Continue with the same Entry

The following calls update and remove the Entry created above. Both operations use its current business identity.

Illustrative continuation. The command bus is injected. These calls are not executed by this guide.

use Backendbase\Domain\ExampleCatalog\Contracts\Command\ChangeEntry;
use Backendbase\Domain\ExampleCatalog\Contracts\Command\RemoveEntry;
use Backendbase\Domain\ExampleCatalog\Domain\EntryIdentity;
use Backendbase\Domain\ExampleCatalog\Domain\EntryType;

$identity = new EntryIdentity(EntryType::SYSTEM, null, 'settings', 'page-size');
$change = new ChangeEntry($identity);
$change->setValue('30');
$commandBus->handle($change);
// The companion query now returns lookupValue="30".

$commandBus->handle(new RemoveEntry($identity));
// The companion query now returns null.

Removal sets a timestamp. It does not delete the row. Setting isActive=false alone does not remove the Entry.

Authorization belongs before repository calls or effects when a named privilege applies. Carry typed AccessControl for such use cases.

AddEntry currently has no named application privilege. Its HTTP route applies API-key and USER authentication. Do not infer ownership from its target identifier.

A public creation identifier can be generated before dispatch. Keep HTTP status, headers, and response keys outside the command.

04 / Write repositories

Map aggregate state at the storage boundary

When: Add a write repository when a use case must persist or reload an aggregate. Reuse the existing port for the same aggregate.

Where: Declare the port in Contracts. Implement it in Adapters/Persistence/Doctrine. Put mapped records in its Entity directory.

How: Expose aggregate operations in the port. Keep SQL, Doctrine objects, and storage failures behind the adapter.

Current port declaration. Namespace and imports are omitted.

interface EntryWriteRepository
{
    public function add(Entry $entry): void;
    public function getActive(string $entryId): Entry;
    public function getActiveByIdentity(EntryIdentity $identity): Entry;
    public function save(Entry $entry): void;
}

Source: src/Backendbase/Domain/ExampleCatalog/Contracts/EntryWriteRepository.php.

Current source excerpt: Doctrine EntryWriteRepository::add(). Enclosing class and imports are omitted.

public function add(Entry $entry): void
{
    try {
        $this->entityManager->persist(ExampleTable::fromDomain($entry));
        $this->entityManager->flush();
    } catch (UniqueConstraintViolationException $exception) {
        throw EntryAlreadyExists::create(
            'An active example already uses this identity.',
            previous: $exception,
        );
    }
}

Source: src/Backendbase/Domain/ExampleCatalog/Adapters/Persistence/Doctrine/EntryWriteRepository.php.

The adapter converts Entry to ExampleTable. It translates duplicate identity storage errors into EntryAlreadyExists.

getActiveByIdentity() reconstructs an aggregate. save() synchronizes its mapped record. A lookup without a nonremoved match raises ResourceNotFound.

Here “active” repository lookup means deleted_at IS NULL. It does not require is_active = 1.

The repository flushes during add and save. A flush sends writes to the database. It does not commit an already active outer transaction.

The command transaction must already be open. Repository methods alone do not atomically coordinate business writes, subscribers, and outbox rows.

FileHow to extend it
Domain/Entry.phpAdd behavior and invariant checks. Keep persistence annotations out.
Domain/EntrySnapshot.phpCarry validated persisted state. Preserve existing timestamps during reconstruction.
Entity/ExampleTable.phpDeclare mapped fields directly. Convert with fromDomain(), synchronize(), and toDomain().
Memory/EntryWriteRepository.phpImplement the same port for deterministic tests. Share EntryStore with the memory read adapter.

Mapped entities must not extend another class. Derive each name from its full table name. example_table maps to ExampleTable.

New business tables use business names without context prefixes. example_table is the documented exception.

For new JSON object state, follow the typed JSON column policy.

example_table.details is an exception. Preserve primitive EntryDetails, JSON_OBJECT mapping, nested shapes, and the documented legacy empty-list read behavior.

See Persistence and Database for mapping rules.

05 / Read adapters

Return a projection without loading an aggregate

When: Add or extend a read adapter when the query needs a new projection or lookup. A query does not require a new table.

Where: Put the read port in Contracts. Keep database code and row mapping under Adapters/Persistence/Doctrine.

How: Bind SQL values. Select the required columns. Validate persisted rows. Return the declared read model, page, scalar, or null.

Current source excerpt: Doctrine EntryReadRepository::getEntryByCriteria(). Enclosing class and imports are omitted.

public function getEntryByCriteria(GetEntryByCriteria $query): EntryDetails|null
{
    [$targetCondition, $parameters] = self::targetCondition($query->type(), $query->typeTargetId());
    $parameters['lookupGroup']      = $query->group();
    $parameters['lookupKey']        = $query->key();
    $row                            = $this->connection->fetchAssociative(
        'SELECT uuid, type, type_target_id, lookup_group, lookup_key, lookup_value, details, is_active,'
        . ' COALESCE(updated_at, created_at) AS updated_at, created_at FROM ' . self::TABLE
        . ' WHERE type = :type AND ' . $targetCondition
        . ' AND lookup_group = :lookupGroup AND lookup_key = :lookupKey'
        . ' AND deleted_at IS NULL LIMIT 1',
        $parameters,
    );
    if ($row === false) {
        return null;
    }

    return EntryReadModelMapper::details($row);
}

Source: src/Backendbase/Domain/ExampleCatalog/Adapters/Persistence/Doctrine/EntryReadRepository.php.

targetCondition() emits IS NULL for a null target. A non-null target uses a bound parameter.

EntryReadModelMapper::details() validates scalar columns, timestamps, and JSON before constructing the projection.

This query excludes removed rows. It can return rows with isActive=false. Preserve that distinction in tests.

List reads count all matching rows. They apply limit and offset in SQL and order by created_at ASC, id ASC.

Group reads count distinct groups before pagination. The memory adapter must preserve the same visible behavior.

Review indexes for every new SQL or Doctrine lookup. Reuse a suitable existing prefix before adding another index.

The current metadata includes criteria, group, and ordered-entry indexes. Include metadata and a forward migration when a new query needs an index.

Use representative MySQL EXPLAIN plans on an identified, prepared target. SQLite tests do not prove MySQL optimizer choices.

Source: src/Backendbase/Domain/ExampleCatalog/Contracts/EntryReadRepository.php.

Source: src/Backendbase/Domain/ExampleCatalog/Adapters/Persistence/Doctrine/EntryReadModelMapper.php.

Source: src/Backendbase/Domain/ExampleCatalog/Adapters/Persistence/Memory/EntryReadRepository.php.

See query index guidance and database tests.

06 / Event definitions

Choose the event path before publishing

When: Add an event when another operation must react to a completed business fact. A write does not always need an event.

Domain events and integration events use different dispatch paths. Neither path is created automatically by calling an aggregate method.

KindWhereHow and when
Domain eventContracts/DomainEvents with listener in Application/DomainEventListener.Implement DomainEvent and use DomainEventTrait. Supply an explicit occurrence time. Publish through DomainEventPublisher for an in-process reaction.
Integration eventContracts/IntegrationEvents with payload in Contracts/IntegrationEvents/V1.Implement IntegrationEvent and use IntegrationEventTrait. Declare name, version, queue flag, arguments, and explicit occurrence time. Return the event from transactional work.
External carrierContracts/ExternalIntegrationEvents/V1.Implement EventMessage for a queue-delivered contract. Register its event name and version. It is not the producer event object.

The domain event targets one listener

The current domain EntryAdded uses #[DomainEventListenerAttribute(EntryAddedListener::class)].

ContainerAwareDomainEventPublisher::publish() reads that attribute, resolves the listener from the container, and calls handle(DomainEvent): void.

This attribute links one listener in the same context. It is not a subscriber entry in ServiceProvider::getIntegrationEventSubscribers().

A missing listener attribute or wrong listener interface fails explicitly. Keep this path only when an in-process domain reaction is required.

07 / Subscribers

Define the reaction and register its type

When: Add a subscriber when a business reaction is required. Publishing an integration event does not require a local subscriber.

Where: Keep local subscribers in Application/IntegrationEventSubscribers. Keep queue subscribers in Application/ExternalIntegrationEventSubscribers/{SourceService}.

How: Implement the matching interface. Declare getSubscribedEvents(). Use injected ports for work and register the subscriber in the context provider.

TypeMethodsProcessing rule
Local integration subscriberIntegrationEventSubscriber: handle(IntegrationEvent): void and getSubscribedEvents(): array.Subscribe to the producer name, such as Example_NewExampleAdded. Work runs synchronously before producer commit.
External integration subscriberExternalIntegrationEventSubscriber: handle(EventMessage): void and getSubscribedEvents(): array.Subscribe to Example_NewExampleAdded_Event. Work runs in a separate consumer inbox transaction.

Current source excerpt: EntryAddedSubscriber::handle(). Enclosing class and imports are omitted.

public function handle(IntegrationEvent $integrationEvent): void
{
    $this->logger->debug('EntryAddedSubscriber', [
        'eventName' => $integrationEvent->eventName(),
        'eventVersion' => $integrationEvent->eventVersion(),
    ]);
}

Source: src/Backendbase/Domain/ExampleCatalog/Application/IntegrationEventSubscribers/EntryAddedSubscriber.php.

The current local subscriber returns [EntryAdded::EVENT_TYPE] from getSubscribedEvents(). It logs event name and version only.

The current external subscriber expects EntryAddedMessage through PHPDoc. It logs metadata only. Neither Entry subscriber maintains another business table.

For a required database reaction, inject a context-owned port. Keep all writes on the transaction connection. Let failures propagate.

Keep provider calls, filesystem writes, processes, and direct broker publication outside local subscribers. Database rollback cannot undo those effects.

Do not log complete event payloads. Use stable metadata that does not expose stored content.

The reference listeners emit diagnostic logs. Those logs cannot roll back with database writes. They are not durable business effects.

Construction is part of the contract

The subscriber registry creates a fresh instance through reflection. Declare an explicit constructor, including an empty constructor without dependencies.

Constructor arguments resolve from the container by type, then by parameter name. Binding the subscriber class itself does not control this construction.

Test registration through the event manager. Instantiating the subscriber directly does not prove the real construction path.

08 / Publish and commit

Publish inside the transaction; deliver later

When: Use a transaction when business writes and related local or outbox writes must succeed together.

Where: Select the boundary in the command handler or its application service. Depend on the shared IntegrationEventTransaction port.

How: Pass a callback that performs authoritative work and returns a complete integration event. Do not publish directly to a broker.

Current source excerpt: EntryEventTransaction::execute(). Enclosing class and imports are omitted.

public function execute(callable $work, callable|null $domainEventFactory = null): void
{
    $transaction = $this->transaction;
    $publisher   = $this->publisher;
    $transaction->execute(static function () use ($work, $domainEventFactory, $publisher): IntegrationEvent {
        $event = $work();
        if ($domainEventFactory !== null) {
            $domainEvent = $domainEventFactory($event);
            $publisher->publish($domainEvent);
        }

        return $event;
    });
}

Source: src/Backendbase/Domain/ExampleCatalog/Application/EntryEventTransaction.php.

EntryEventTransaction adds the optional domain publication inside the shared transaction callback. AddEntry supplies that factory; other writes can omit it.

Read the text version of this flow
  1. AddEntryHandler enters EntryEventTransaction. The Doctrine wrapper opens the transaction before running work.
  2. EntryWrites reads the clock, creates Entry, and writes through the repository. It returns the integration event.
  3. The context wrapper publishes the domain event. Then the integration event manager runs local subscribers and appends the optional outbox row.
  4. The Doctrine wrapper flushes and commits. Any failure rolls back database work. Queue publication can start only after commit.

Current source excerpt: DoctrineIntegrationEventTransaction::execute(). Enclosing class and imports are omitted.

public function execute(callable $transactionalWork): void
{
    $eventManager  = $this->eventManager;
    $entityManager = $this->entityManager;
    $connection    = $entityManager->getConnection();
    try {
        $connection->transactional(static function () use ($transactionalWork, $eventManager, $entityManager): void {
            $event = $transactionalWork();
            $eventManager->dispatchEvent($event);
            $entityManager->flush();
        });
    } catch (Throwable $exception) {
        $entityManager->clear();

        throw $exception;
    }
}

Source: src/Backendbase/Infrastructure/Adapters/Persistence/Doctrine/DoctrineIntegrationEventTransaction.php.

The order is: database work → domain listener → local integration subscribers → optional outbox append → final flush → commit.

The repository can flush earlier. All flushes still belong to the open transaction. The wrapper clears the EntityManager after a failure and rethrows.

Use the same connection for the transaction wrapper, subscriber repositories, and outbox writer. Independent connections cannot share this commit.

occurredOn() preserves the mutation instant. The outbox stores it as occurred_at. Its own clock reading supplies created_at.

In this code, “fire an event” means DomainEventPublisher::publish() or transactional EventManager::dispatchEvent(). There is no separate fire API.

The command and query buses only resolve and call handlers. They do not supply transactions, validation, authorization, asynchronous dispatch, or retry.

Source: src/Backendbase/Infrastructure/Adapters/EventManager/ContainerAwareEventManager.php.

Source: src/Backendbase/Infrastructure/Adapters/Persistence/Doctrine/DoctrineIntegrationEventOutbox.php.

10 / Conditional queue delivery

Handle committed events in a separate transaction

When: Use queue delivery when a reaction must run outside the producer transaction or in another service.

Where: Keep versioned carriers and external subscribers in the context. Shared relay and consumer mechanics stay in infrastructure.

How: Set the producer queue flag. Register the external carrier and subscriber. Use the existing outbox and inbox pipeline.

Read the text version of this flow
  1. The relay claims a committed outbox row, publishes through the selected transport, and records publication success or retry state.
  2. The processor validates message identity, destination, event name, event version, and replay eligibility. It adds _Event to the producer event name.
  3. The inbox opens a separate transaction. The dispatcher maps the payload to the registered carrier and calls external subscribers.
  4. The inbox flushes subscriber database work and records processed_at before commit. Success acknowledges. A processed duplicate does not dispatch again.

EntryAddedMessage contains typed outer data and an EntryAddedCommand carrier. It rejects different outer and nested identifiers.

The dispatcher resolves the event name and version through the actual registry. Valinor reconstructs the carrier before dispatchExternalEvent().

External dispatch does not append the received event to the outbox again. The present Entry queue subscriber logs metadata only.

The replay window accepts occurrence times within the previous seven days. Missing, malformed, future, or older times fail permanently.

The outbox can retry beyond that window. Monitor pending age before retained events become ineligible for consumption.

Registration does not start workers or configure broker topology. Queue delivery also needs configured transports and supervised relay and consumer processes.

Source: ReplayWindow. See queue runtime for worker setup.
