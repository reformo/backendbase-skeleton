# Internationalization and Tolgee

Runtime translation reads local PHP dictionaries from `resources/i18n`. It does not call Tolgee or Redis during HTTP requests.

## Runtime rules

- Check only the first comma-separated `Accept-Language` value, without its quality weight. Do not scan later values.
- Use `tr-TR` when the header is missing, empty, or unsupported.
- Use exact locale filenames.
- Store nested arrays with stable dotted keys.
- Keep placeholder names equal across locales.
- A missing key returns its locale-qualified key.
- There is no per-key fallback to the default dictionary.

Tolgee is a source synchronization tool only:

```sh
bin/tolgee/sync-local-keys
bin/tolgee/sync-remote-keys
```

`sync-local-keys` creates missing remote keys. `sync-remote-keys` replaces local locale files from an export.

Protect `TOLGEE_API_KEY`. Run only one file-writing synchronization process at a time.

Verify existing explicit authority covers the direction, project, namespace, locales, and create-or-replace effects before writing. Ask only for missing authority or materially changed scope. A local translation edit alone does not authorize synchronization.

Current issue: `en-US.php` requires `tr-TR.php`, so English responses currently contain Turkish values.
