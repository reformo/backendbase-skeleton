Environment and Configuration

Overview

Backendbase loads configuration from PHP arrays. Environment variables supply deployment values. ConfigAggregator merges shared files with one API-specific directory. Typed configuration objects validate the merged values and expose focused settings to runtime services.

Read

Environment values

backendbaseEnv() reads $_ENV, then the process environment, then a code default.

Merge

Configuration arrays

Shared config/autoload values load first. The selected API configuration loads second.

Consume

Container services

Factories resolve typed settings and inject focused objects into runtime services.

Never treat .env.example as a secret store It is tracked source. Use placeholders only. Store production secrets in the deployment platform or a secret manager.

Value precedence and types

01 · FIRST$_ENV[$key]
An existing environment array value wins.
02getenv($key)
Use the process value when $_ENV has no key.
03Code default
Use the supplied fallback when the variable is absent.
04Strict parser
Numeric helpers reject malformed integer and float text.
05Typed boundary
A settings object validates the merged value before adapter construction.
function backendbaseEnv(string $key, mixed $default = null): mixed
{
    if (array_key_exists($key, $_ENV)) {
        return $_ENV[$key];
    }

    $value = getenv($key);

    return $value === false ? $default : $value;
}
  • An empty string is a present value. It does not activate the default.
  • Most environment values remain strings.
  • Ports, counts, and timeouts use strict integer or finite-float environment helpers.
  • AWS_SQS_CONTINUOUS uses FILTER_VALIDATE_BOOL.
  • Settings::get() remains inside configuration boundary objects.
  • Runtime code uses typed settings for application, database, queue, AWS, Redis, logging, HTTP, and JWT values.
  • SQS, SNS, RabbitMQ, readiness, and AWS client adapters receive immutable leaf settings objects.
  • External Software Development Kit builders create arrays only at the vendor call boundary.

Malformed numeric text fails during configuration loading. Error messages identify the environment key without including its value.

Dotenv::createUnsafeImmutable() loads local values without replacing values that the process already supplied.

An unknown public mode is treated as production during early bootstrap. The raw unknown value can still fail later when code calls Settings::env().

Database and Doctrine

Application

Container connection

config/dependencies/doctrine.php parses BACKENDBASE_DB_DSN with a MySQL-to-pdo_mysql DSN mapping.

Doctrine ORM finds shared and bounded-context entity paths through PathFinder.

CLI

bin/doctrine

The Doctrine entry point loads the optional .env, merges shared, ExampleApi, and console configuration, then builds its own entity manager.

Development uses ArrayAdapter. Other modes use var/cache/doctrine.

Keep credentials out of commands and logs Supply the DSN through the environment. Do not paste a production DSN into documentation, shell history, or source files.

Messaging configuration

Driver selection

BACKENDBASE_QUEUE_DRIVER defaults to rabbitmq. The queue factory accepts only rabbitmq or sqs.

RabbitMQ

Connection and topology

  • BACKENDBASE_RABBITMQ_HOST, PORT, USER, PASSWORD, and VHOST
  • QUEUE, EXCHANGE, and EXCHANGE_TYPE
  • DEAD_LETTER_EXCHANGE and DEAD_LETTER_QUEUE_SUFFIX
  • CONNECTION_TIMEOUT, READ_WRITE_TIMEOUT, HEARTBEAT, and PREFETCH_COUNT

Message retention is fixed in code at seven days.

AWS

SQS and SNS

  • AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY
  • AWS_REGION defaults to eu-central-1.
  • AWS_ENDPOINT supports compatible local or private endpoints.
  • SQS queue name, URL, batch count, wait, visibility, and continuous mode
  • SNS SMS type and sender ID

AWS_SECRET_KEY is a compatibility fallback for the secret key.

AWS credentials must both be empty or both be non-empty. The shared AWS factory rejects a partial pair.

The tracked example file contains concrete-looking secret samples Treat them as exposed placeholders. Do not reuse them. Replace them with neutral placeholders and rotate any value that was used outside local development.
  • Do not commit .env.
  • Do not log full settings arrays.
  • Do not print tokens or connection strings.
  • Use separate values for each environment.
  • Rotate credentials after suspected exposure.
  • Keep least-privilege service permissions.

Cache and configuration changes

The public API stores its merged configuration under var/cache/{api-slug}/merged-conf.php. When that file exists, bootstrap does not load .env.

01Change secret
Update the deployment environment or local .env.
02Clear cache
Remove merged config, route, container, and Doctrine caches.
03Restart
Restart long-running workers and API processes.
04Resolve services
Exercise database, Redis, and the active queue driver.
05Verify
Check health, logs, and one safe request.
bin/backendbase clear-cache
Current exit-code behavior ClearCache deletes cache contents but returns 1. Automation can interpret the command as failed even after deletion.

Validation and failure behavior

There is no single configuration schema. Focused settings objects validate merged values when PHP-DI resolves each object. Runtime services receive typed leaf settings instead of generic configuration arrays.

Environment modeApplicationRuntimeSettings resolutionAn unknown value fails enum conversion.

Logger levelConfig file loadAn invalid Monolog level name fails configuration evaluation.

RedisRedisSettings resolutionRejects invalid host, port, or readiness values before client construction.

PHP-DI creates many services lazily. A successful container build does not prove that every external-service configuration is valid.

Local setup workflow

  1. Copy .env.example to an untracked .env.
  2. Replace every secret-like sample with a new local-only value.
  3. Add current variables that the example file omits.
  4. Select BACKENDBASE_ENV=dev.
  5. Start MySQL, Redis, and the selected queue driver.
  6. Clear stale runtime caches.
  7. Run focused configuration and dependency tests.
  8. Start the API and verify one health request.
cp .env.example .env
docker compose up -d
bin/backendbase clear-cache
composer run start-apis

Do not use the example credentials for any shared, stage, or production environment.

Review checklist

  • The environment mode uses an exact enum value.
  • Numeric environment values contain valid integer or finite decimal text.
  • Every required secret comes from a protected source.
  • No tracked file contains a live credential.
  • The database DSN points to the intended database.
  • Only one queue driver is selected.
  • Queue timeouts match worker behavior.
  • AWS credential keys are both present or both absent.
  • Redis is available before JWT use.
  • CORS origins match the deployed clients.
  • The JWT audience matches the API.
  • Logger output and level match the runtime.
  • Configuration caches were cleared after changes.
  • Long-running workers were restarted.
  • External-service factories were resolved in checks.
  • Stage does not expose unwanted error details.
  • .env.example matches current variable names.
