Overview

A Use Case API is an HTTP adapter under src/Backendbase/Infrastructure/UseCase/{ApiName}. It owns transport concerns. It does not own domain rules or persistence.

Select

Choose the API

The shared bootstrap uses X-Source-Id to select the use-case directory and configuration slug for both public entry points.

Translate

Adapt HTTP input

Routes and actions turn headers, paths, queries, and JSON into commands or queries.

Return

Shape HTTP output

Actions convert read models and domain errors into status codes, JSON, headers, or empty responses.

Current reference The repository contains one consumer API: ExampleApi. Do not assume that another API exists before you scaffold it.

Request lifecycle

The shared bootstrap builds the runtime. The selected API supplies only its middleware and routes.

Entry points and bootstrap

Dedicated

public/example-api/index.php

Sets API name and slug variables, then includes the shared bootstrap. The bootstrap does not read those variables; this path still requires X-Source-Id: example.

Development base URL: http://127.0.0.1:8080/example-api.

Shared selector

public/index.php

Reads X-Source-Id. The current mapping is example → ExampleApi / example-api.

A missing or unknown source ID ends bootstrap before Slim starts.

Middleware and security

API metadata

Request attributes

The API middleware sets apiName, apiKeyHeaderName, and useIdentifierAsApiKey.

Client IP

Proxy header scan

IpAddress stores the resolved address in the ClientIp request attribute.

Bearer token

Protected route group

The authorization middleware validates a Redis-backed JSON Web Token and adds user, timezone, and access-control attributes.

The shared bootstrap also adds body parsing, routing, error middleware, a shutdown handler, and the response emitter.

API-key validation is active ExampleApi/middleware.php adds ValidateApiKey::class. It validates Backendbase-Api-Key on non-public paths and returns status 401 for a missing or invalid key.

Protected routes expect Authorization: Bearer <accessToken>. Missing or invalid bearer data returns status 401.

Controller pattern

Business handlers extend Backendbase\Shared\Http\Actions\Action. The transport-only Liveness handler is directly invokable. The base class stores the PSR-7 request, response, and route arguments before it calls action().

final class EntryAction extends Action
{
    public function __construct(
        private readonly QueryBus $queryBus,
        protected LoggerInterface $logger,
    ) {
        parent::__construct($logger);
    }

    protected function action(): Response
    {
        $type = ExampleRequestInput::type(
            $this->request->getAttribute('type-slug'),
        );
        $params = PayloadSanitizer::sanitize(
            $this->request->getQueryParams(),
        );

        $result = $this->queryBus->handle(new EntryQuery($type));

        return new JsonResponse(['data' => $result], 200);
    }
}

Controller responsibilities

  • Read path, query, header, and parsed-body data.
  • Sanitize and validate untrusted input.
  • Create one command or query for the operation.
  • Map a read model to the response schema.
  • Select the HTTP status and response headers.

Do not put here

  • SQL or Doctrine repository calls.
  • Aggregate state changes.
  • Outbox or queue publishing.
  • Reusable business decisions.
  • Database transaction control.

Current boundary validation

ExampleRequestInput validates the example type, integers, strings, objects, and booleans. Invalid data raises InvalidUserInput before bus dispatch.

  • typeSlug must map to an EntryType.
  • typeTargetId accepts null, an empty string, or a positive integer.
  • pageSize and page default to 1000 and 1.
  • PATCH treats omitted and null lookupValue, details, and isActive fields as unchanged. Other supplied values must be a string, object, and boolean.
  • PayloadSanitizer processes query and parsed-body arrays before use.
Validate all new fields at the boundary The current helper covers only selected fields. Do not rely on PHP casts as complete request validation.

CQRS dispatch

Read

Query action

  1. Validate path and query data.
  2. Create a typed query contract.
  3. Call QueryBus::handle().
  4. Map the read model to response JSON.
  5. Return status 200.
Write

Command action

  1. Validate path and JSON data.
  2. Create the typed public resource identity.
  3. Create a typed command contract.
  4. Call CommandBus::handle().
  5. Return status 204.

ChangeExampleDetails and RemoveExample put EntryIdentity in one command. Their handlers resolve the aggregate through the write repository and own the resource-not-found decision.

Configuration and cache

The bootstrap merges shared configuration and API-specific configuration. Production can compile the dependency container and cache routes.

  • API version 1.0.0
  • EXAMPLE_API_KEY
  • Route cache: var/cache/example-api/routes.php

config/example-api/jwt.global.php

  • Alias, issuer, and audience
  • BACKENDBASE_JWT_SIGN_KEY
  • Token duration PT24H

http-headers.global.php

  • Allowed CORS origins
  • Allowed request headers

Shared settings

  • Environment and error visibility
  • BASE_PATH and CDN_BASE_URL
  • Logger, database, Redis, queue, and object-store settings

When no cached merged configuration exists, the bootstrap loads .env. It then selects development or production behavior from BACKENDBASE_ENV.

Tests and Bruno

PHPUnit

HTTP adapter tests

  • Input validation stops bus dispatch.
  • Missing write resources are reported by the command handler after dispatch.
  • Read actions map projections.
  • Write actions create correct commands.
  • Module routing has four Account routes, six Example routes, one Greeting route, and sixteen total routes including root and fallback routes.
  • Root, authentication, and fallback responses are stable.
Bruno

End-to-end collection

Fifteen YAML requests cover system status, authentication, the account and Example lifecycles, and queued greeting delivery.

The local environment points to http://127.0.0.1:8080/example-api.

Each run writes an HTML report under artifacts/bruno/example-api.

vendor/bin/phpunit tests/Infrastructure/UseCase/ExampleApi
bin/bruno example-api local

Run PHPUnit without external services when possible. Bruno requires the API, configured dependencies, and a prepared account.

Add an endpoint

  1. Define the OpenAPI path, operation, headers, security, input schema, response schema, and errors.
  2. Add or reuse a bounded-context command or query contract.
  3. Add domain behavior, ports, adapters, and handlers before the HTTP controller.
  4. Create an Action under the affected API module.
  5. Sanitize and validate all untrusted input before bus dispatch.
  6. Add the route to ModuleConfig.
  7. Group the route with AuthorizationMiddleware by default.
  8. Add focused controller and routing tests.
  9. Regenerate the OpenAPI file.
  10. Add or update the Bruno request when end-to-end coverage is required.
  • Request names use camelCase.
  • URL path parameters use kebab-case conventions.
  • Response attributes use camelCase.
  • Success and error statuses match OpenAPI.
  • The controller does not access Doctrine.
  • Invalid input never reaches a bus.
  • Write handlers own the missing-resource decision.
  • All affected consumer APIs are updated.

Current constraints and specification gaps

Current behaviorImpact
The CORS allow-header list omits Accept-Language.Browser preflight can reject requests that send this documented header.
The shared selector writes a payload with status 400 but does not set the HTTP status before die().Clients must not assume that the transport status matches that early payload.
Authenticate verifies an active account and its Argon2id password hash.The protected Account module registers, revises, retires, and lists accounts through ACL-checked commands and a query.
Header references are not general runtime validators.Several headers are required by OpenAPI but may be absent at runtime.
Request validation covers selected fields only.New fields need explicit type, format, range, and required-value checks.
Group queries return EntryGroupPage.The response includes the complete distinct-group total and the requested page.
OpenAPI output is generated.A source YAML change has no public effect until the merged file is regenerated.
