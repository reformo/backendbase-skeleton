01 · Overview

The runtime reads local PHP dictionaries

Translator does not call Tolgee while it handles an HTTP request. The dependency container loads resources/i18n/*.php and selects one local locale.

Runtime

Loads local files and translates keys.

Source workflow

Synchronizes local keys with Tolgee.

Deployment

Must deliver generated local dictionaries.

02 · Runtime flow

Translation stays inside the process

  1. Requesthas Accept-Language
  2. Containerselects locale
  3. PHP filesload dictionaries
  4. Translatorlooks up key
  5. Valuesreplace placeholders
  6. Callerreceives text or array

This flow has no runtime network request and no runtime Redis dependency.

03 · Locale selection

Use the first supported Accept-Language value

  1. Read HTTP_ACCEPT_LANGUAGE.
  2. Use tr-TR when the header is missing or empty.
  3. Take the first comma-separated language value.
  4. Remove its optional quality weight.
  5. Use tr-TR when no matching PHP file exists.
The current selector does not negotiate language ranges. For example, en does not match en-US.php.

04 · Dictionaries

Use nested arrays with stable dotted keys

return [
    'general' => [
        'error' => 'Unclassified error: :error',
    ],
];

The translator prefixes the dotted key with the selected locale. general.error becomes en-US.general.error inside the combined dictionary.

05 · Translation calls

Replace named placeholders after lookup

$translator->translate('general.error', ['error' => $message]);
$translator->_('general.command-failed');
$translator->translate('general.error', ['error' => $message], 'tr-TR');

Each value key replaces the matching colon placeholder. A translation can also return a nested array.

06 · Missing keys

A missing translation returns its locale-qualified key

When lookup fails, Translator returns a value such as en-US.general.unknown. It does not fall back to another dictionary.

This visible key makes missing content easy to detect. It can also expose internal key names in client responses.

07 · Tolgee role

Tolgee supports source synchronization

The repository has two executable scripts. They compare or replace local locale files through the Tolgee API. Both scripts use shared validation and HTTP support from bin/tolgee/sync-support.php.

  1. Local filescontain service keys
  2. Sync scriptloads configuration
  3. Tolgee APIcreates or exports keys
  4. Service prefixselects owned keys
  5. PHP writerreplaces locale files
  6. Runtimeloads local result

08 · Local to Tolgee

Create remote keys that are missing

bin/tolgee/sync-local-keys loads local files and creates keys that do not exist in Tolgee. It does not replace existing remote translations.

TOLGEE_API_KEY='project-key' bin/tolgee/sync-local-keys

09 · Tolgee to local

Replace local locale files with a remote export

bin/tolgee/sync-remote-keys exports service-prefixed translations. It writes temporary files and then replaces each local PHP file.

TOLGEE_API_KEY='project-key' bin/tolgee/sync-remote-keys
Review version-control changes after a remote sync. This command changes tracked translation source files.

10 · Commands and cron

Run synchronization outside request handling

# Show command help
bin/tolgee/sync-local-keys --help
bin/tolgee/sync-remote-keys --help

# Example source synchronization every 15 minutes
*/15 * * * * cd /srv/backendbase && bin/tolgee/sync-remote-keys >> var/logs/tolgee-sync.log 2>&1
Choose only one service instance to run a synchronization cron. Concurrent writers can replace the same local files.

11 · Security and limits

Protect the project API key and bound HTTP work

  • TOLGEE_API_KEY is required and must stay in secret storage.
  • TOLGEE_API_URL defaults to https://app.tolgee.io.
  • The shared HTTP client uses a 10-second connection timeout.
  • The shared HTTP client uses a 30-second request timeout.
  • The script checks HTTP status and response content.
  • Do not write the API key to logs or commands stored in shell history.

12 · Current differences

Source behavior differs from the Tolgee skill text

  • The skill describes a bin/backendbase tolgee:sync command. The current source has two scripts under bin/tolgee.
  • The skill describes Redis-backed runtime translations. The current Translator reads only local PHP files.
  • en-US.php currently requires tr-TR.php. English responses therefore contain Turkish values.
  • The locale selector supports exact filenames only.
  • There is no fallback from a selected locale to a default dictionary for a missing key.

13 · Tests

Verify lookup, synchronization, and file safety

vendor/bin/phpunit tests/Shared/Services/SharedServicesTest.php
bin/tolgee/sync-local-keys --help
bin/tolgee/sync-remote-keys --help

Use a local HTTP test server or client doubles for synchronization tests. Do not call a live Tolgee project from the test suite.

14 · Checklist

Add or change translations safely

  • Every supported locale has one PHP file.
  • Each file returns the same key shape.
  • Placeholders have the same names in all locales.
  • The default locale has a value for each key.
  • Tolgee keys use the expected service prefix.
  • The API key stays outside source.
  • Only one synchronization process writes local files.
  • Runtime and synchronization tests pass.
