Command Query Responsibility Segregation

Use commands for state changes and queries for read results. Resolve one handler through an attribute or context registry and keep input validation at the adapter boundary.

Overview

Command Query Responsibility Segregation (CQRS) separates state-changing requests from read requests. Backendbase uses a small in-process bus for each path.

Commands write

A command handler changes domain state and returns no result.

Queries read

A query handler returns a typed read model, scalar, list, page, or null.

One handler

Each command or query resolves one handler from its attribute or context registry mapping.

Separation goal Commands protect domain invariants through aggregates. Queries use direct read projections without loading aggregates.

Architecture

The adapter creates a contract. The bus resolves its handler. The handler uses the correct persistence port.

Core contracts

The CQRS design uses shared contracts, context registry mappings, and two Infrastructure bus adapters.

Query serialization differs from command serialization Command requires toArray() and jsonSerialize(). Query requires only jsonSerialize(), although current queries also expose toArray().

Handler resolution

Both buses use the configured handler source, then resolve the handler from the container.

  1. Read the concrete command or query class.
  2. Read the owning context's registry mapping.
  3. Resolve that handler class from the PSR container.
  4. Verify the command or query handler interface.
  5. Call handle() with the original contract object.

Registry mode

public static function getHandlers(): array
{
    return [ChangeEntry::class => ChangeEntryHandler::class];
}
Choose one handler source The config/dependencies.php provider defaults to RegistryHandlerResolver::class. It reads mappings from each context's ServiceProvider::getHandlers(). AttributeHandlerResolver remains available for separately attributed contracts. It cannot dispatch the current commands and queries.

Bus implementation

public function handle(Command $command): void
{
    $handlerFQCN = $this->handlerResolver->handlerFor($command);

    $handler = $this->container->get($handlerFQCN);
    if (! $handler instanceof CommandHandler) {
        throw new UnexpectedValueException(
            $handlerFQCN . ' is not a command handler.',
        );
    }

    $handler->handle($command);
}

Command path

A command expresses an accepted intent to change state. It does not return domain data.

Command contract

readonly class RemoveEntry implements Command
{
    public function __construct(
        private EntryIdentity $identity,
        private AccessControl $accessControl,
    ) {
    }

    public function identity(): EntryIdentity
    {
        return $this->identity;
    }

    public function accessControl(): AccessControl
    {
        return $this->accessControl;
    }

    public function jsonSerialize(): mixed
    {
        return $this->toArray();
    }

    public function toArray(): array
    {
        return ['identity' => $this->identity->toArray()];
    }
}

Command handler

readonly class RemoveEntryHandler implements CommandHandler
{
    public const string REQUIRED_PRIVILEGE = 'example.remove';

    public function __construct(
        private EntryWriteRepository $entryRepository,
        private IntegrationEventTransaction $integrationEventTransaction,
    ) {
    }

    /** @param RemoveEntry $command */
    public function handle(Command $command): void
    {
        $command->accessControl()->isAllowed(self::REQUIRED_PRIVILEGE);
        $this->integrationEventTransaction->execute(
            function () use ($command): EntryRemoved {
                $entry = $this->entryRepository
                    ->getActiveByIdentity($command->identity());
                $entry->remove();
                $this->entryRepository->save($entry);

                return new EntryRemoved($entry->id());
            },
        );
    }
}

Command rules

  • Use intention-revealing names such as AddEntry or RemoveEntry.
  • Convert external primitives into enums, value objects, and validated values before construction.
  • Carry only the data needed for one use case.
  • Dispatch one command from the controller and resolve authoritative state in the handler.
  • Put business decisions on the aggregate, not in the controller.
  • Use the write repository port for aggregate persistence.
  • Start required transactions inside the handler or a called application service.
  • Return no data through CommandBus. Use a generated ID before dispatch when the response needs it.
Patch commands can carry nullable fields The current ChangeEntry command uses nullable values to mean “not supplied.” Its handler passes those values to aggregate behavior.

Query path

A query describes requested data and declares its result through PHPDoc generics.

Query contract

/** @implements Query<EntryDetails|null> */
final readonly class GetEntryByCriteria implements Query
{
    public function __construct(
        private EntryType $type,
        private int|null $typeTargetId,
        private string $group,
        private string $key,
    ) {
    }

    public function jsonSerialize(): mixed
    {
        return $this->toArray();
    }

    public function toArray(): array
    {
        return [
            'type' => $this->type->value,
            'typeTargetId' => $this->typeTargetId,
            'group' => $this->group,
            'key' => $this->key,
        ];
    }
}

Query handler

/** @implements QueryHandler<GetEntryByCriteria, EntryDetails|null> */
final readonly class GetEntryByCriteriaHandler implements QueryHandler
{
    public function __construct(
        private EntryReadRepository $entryRepository,
    ) {
    }

    /** @param GetEntryByCriteria $query */
    public function handle(Query $query): EntryDetails|null
    {
        return $this->entryRepository->getEntryByCriteria($query);
    }
}

Query rules

  • Use a result type in @implements Query<TResult>.
  • Repeat query and result types on QueryHandler.
  • Return explicit read models, pages, scalars, lists, or null.
  • Use Doctrine Database Abstraction Layer (DBAL) and plain SQL for read projections.
  • Carry typed AccessControl when a query needs a named privilege. Check it in the handler before the read.
  • Do not load or change aggregates on the query path.
  • Do not create integration events from query handlers.
Authorization is not write-only Apply handler authorization to every sensitive command or query. The account.list operation is a protected query.
Generics are static-analysis metadata PHP returns mixed from QueryBus::handle() at runtime. PHPStan uses the template annotations to infer the result at call sites.

HTTP adapter boundary

Controllers translate untrusted HTTP data into one valid command or query for the operation.

  1. Read route, query, or request-body values.
  2. Sanitize the input with PayloadSanitizer.
  3. Validate types, formats, ranges, and enum values.
  4. Create typed primitives such as EntryType and Pagination.
  5. Construct the command or query.
  6. Dispatch once through CommandBus or QueryBus.
  7. Map the result into an HTTP response.

Boundary example

$type = ExampleRequestInput::type(
    $this->request->getAttribute('type-slug'),
);

$params = PayloadSanitizer::sanitize(
    $this->request->getQueryParams(),
);

$typeTargetId = ExampleRequestInput::optionalTypeTargetId(
    $params['typeTargetId'] ?? null,
);

$pageSize = ExampleRequestInput::positiveInteger($params['pageSize'] ?? 1000, 'pageSize');
$page = ExampleRequestInput::positiveInteger($params['page'] ?? 1, 'page');
$pagination = new Pagination($pageSize, $page);

$result = $this->queryBus->handle(
    new GetEntryGroupsByType($type, $typeTargetId, $pagination),
);
The buses are not validation boundaries They accept any object that implements the required interface. They do not validate fields, authorization, HTTP rules, or business invariants.

Authoritative write lookup

The change and remove controllers send EntryIdentity in one command. The handler loads the active aggregate through its write repository inside the transaction. It owns the missing-resource decision and current invariants.

Transactions and events

A bus only routes. A command handler controls write atomicity and event publication.

Bus responsibilities

  • Ask the configured resolver for the handler class
  • Resolve the handler
  • Verify the handler interface
  • Invoke the handler

Handler responsibilities

  • Load required domain state
  • Invoke aggregate behavior
  • Persist through write ports
  • Control database transactions
  • Create domain or integration events when required

Example integration event producers use IntegrationEventTransaction::execute(). It dispatches the returned event to local subscribers before commit. Business writes, local subscriber writes, and the outbox row selected by DELIVER_VIA_QUEUE commit or roll back together.

Do not publish directly from a command handler Use the transactional outbox for business-relevant external effects. See Integration Events for the complete event contract and subscriber flow.

Dependency wiring

PHP-DI provides the buses, handlers, and repository adapters.

Bus definitions

Dependency definitions use the registry resolver by default. Both bus constructors require a handler resolver. Current contracts have no handler attributes.

CommandBus::class => fn (ContainerInterface $container) =>
    new ContainerAwareCommandBus($container, $container->get(HandlerResolver::class)),

QueryBus::class => fn (ContainerInterface $container) =>
    new ContainerAwareQueryBus($container, $container->get(HandlerResolver::class)),

config/dependencies/bounded-contexts.php discovers each context ServiceProvider.php and combines its command and query mappings.

Handler autowiring

'Backendbase\Domain\*\Application\CommandHandlers\*Handler'
    => autowire('Backendbase\Domain\*\Application\CommandHandlers\*Handler'),

'Backendbase\Domain\*\Application\QueryHandlers\*Handler'
    => autowire('Backendbase\Domain\*\Application\QueryHandlers\*Handler'),

Bounded-context service providers bind repository ports to Doctrine adapters. Tests can bind the same ports to memory adapters.

Handler mappings do not register services Registry entries only identify a handler class. The container must still resolve that class and every constructor dependency.

Error behavior

The buses add little error handling. Most exceptions propagate to the calling adapter.

Missing registry mapping in registry modeThe resolver throws UnexpectedValueException.Context ServiceProvider::getHandlers().
Handler is missing from the containerThe PSR container exception propagates.Dependency configuration.
Resolved class has the wrong interfaceThe bus throws UnexpectedValueException.Contract registration.

HTTP problem details Domain errors reach the Infrastructure HTTP error handler. Its mapper converts them into an application/problem+json response. The same handler owns Slim and unexpected failures.

Current constraints and important behavior

These points describe the current implementation, not an extended CQRS framework.

No bus middleware

The buses do not provide validation, logging, tracing, authorization, retries, or transaction middleware.

No asynchronous commands

CommandBus invokes its handler in the current process. It does not enqueue commands.

No runtime generic check

Query result templates help PHPStan. The bus still returns mixed at runtime.

Explicit handler source

The selected resolver uses context registry mappings or handler attributes.

Mutable patch command

ChangeEntry uses setters. Build it fully before dispatch and do not reuse it after dispatch.

Write lookup stays in the handler

Change and remove handlers resolve public identity inside their write transaction. Controllers dispatch one command.

Serialization asymmetry

AddEntry::details() changes null to an empty array, but toArray() keeps the original nullable property.

One handler per contract

The selected handler source names one handler. Fan-out behavior belongs in the handler or an event published after the write.

Implementation checklist

Complete every applicable item for a new use case.

  1. Choose a command for state change or a query for data retrieval.
  2. Create the contract under Contracts/Command or Contracts/Query.
  3. Validate external data before contract construction.
  4. Use enums or value objects for business-bearing primitives.
  5. Map the contract in the owning context's ServiceProvider::getHandlers().
  6. Create the handler under Application/CommandHandlers or Application/QueryHandlers.
  7. Add concrete PHPDoc parameter and generic result types.
  8. Use the write port and aggregate for commands.
  9. Use the read port and projection for queries.
  10. Control transactions and integration events in command orchestration.
  11. Bind new repository ports in the bounded-context service provider.
  12. Test serialization, handler behavior, bus routing, persistence, and HTTP boundaries.
  13. Run PHPStan at level 8 and the focused PHPUnit tests.
