01 · Overview

Notification models are independent from providers

Shared notification primitives describe the delivery request. Infrastructure adapters translate those models to one provider. StackNotifier selects a provider by notification type.

Email

Addresses, sender, subject, HTML, template data, and attachments.

Push

Title, body, topic, device token, image, and string-compatible data.

SMS

E.164 phone number and non-empty message.

04 · Provider stack

Select providers by stable type names

Providers implement Notify and return typed NotificationResult values. StackNotifier stores one provider per type and dispatches each notification in order. Provider clients and raw responses remain inside Infrastructure adapters.

A missing provider raises UnexpectedValueException. Register every type that a producer or queue consumer can create.

05 · SMS with SNS

SNS sends transactional or promotional SMS

SnsNotifier accepts only SmsNotification. It publishes the phone number, message, SMS type, and optional sender identifier through SnsClient.

  • AWS_SNS_SMS_TYPE must be Promotional or Transactional.
  • AWS_SNS_SENDER_ID is optional.
  • The destination uses E.164 format.

06 · Push with Firebase

Firebase maps one push model into CloudMessage

FirebasePushNotifier maps notification text, topic, token, data, Android options, Apple Push Notification Service options, and optional CDN-based images.

Registration state: The adapter exists, but the inspected dependency container does not register it in StackNotifier.

07 · Email state

Email has a model but no registered provider

EmailNotification supports direct HTML, templates, recipients, sender data, and attachments. The repository has environment placeholders for SendGrid and Pusher, but no inspected email notifier adapter is registered.

Runtime mismatch: NotificationMessageProcessor always builds an email notification. The container registers only SnsNotifier, which accepts SMS.

09 · Idempotency

External delivery needs explicit outcome state

ExternalEffectInbox::processOnce() prevents concurrent or repeated provider calls. It distinguishes success, in-progress work, and unknown external outcome.

A provider can accept a request before the process records success. Treat an unknown outcome as a manual or permanent-failure case, not an automatic duplicate send.

11 · Current gaps

Known notification limits

  • The notification queue produces email work without an email provider.
  • Firebase adapter registration is absent.
  • Email properties use mutable fields that can remain uninitialized.
  • The Firebase adapter debug message contains a spelling error.
  • Provider payload logging can include notification content.
  • No end-to-end notification provider test exists.

13 · Checklist

Add a notification type safely

  • The model validates required external data.
  • The provider has one stable type name.
  • The container registers the provider.
  • Secrets stay in configuration.
  • The queue model maps without data loss.
  • Idempotency and unknown outcomes are handled.
  • Logs exclude sensitive content.
  • Failure-policy tests pass.
