05 · OpenAPI source

The root document composes the contract

example-openapi.yml owns the OpenAPI version, title, servers, root operations, security schemes, tags, and path references.

Root document

  • Uses OpenAPI 3.0.0.
  • Defines local, stage, and production servers.
  • Defines bearerAuth and apiKey.
  • References six feature path files.

Feature path files

  • example-groups.yaml owns one GET operation.
  • examples.yaml owns GET and POST operations.
  • example-details.yaml owns GET, PATCH, and DELETE operations.
  • hello.yaml owns POST greeting delivery.
  • accounts.yaml owns GET and POST account operations.
  • account-by-uuid.yaml owns PATCH and DELETE account operations.
paths:
  /example-types/{type-slug}/groups:
    $ref: "./example/example-groups.yaml"
  /example-types/{type-slug}/groups/{example-group}/examples:
    $ref: "./example/examples.yaml"
  /example-types/{type-slug}/groups/{example-group}/examples/{example-key}:
    $ref: "./example/example-details.yaml"

Keep one operation ID for each operation. Keep path parameter names equal to route placeholders.

06 · Shared components

Reuse headers and standard responses

resources/api-docs/common/components.yaml defines shared request headers and response schemas.

HeaderRequirementPurposeBruno variable
Accept-LanguageRequiredResponse languageacceptLanguage
The-Timezone-IANARequiredIANA time zonetimezone
X-Request-IdRequiredRequest correlationrequestId
X-Source-IdRequiredAPI source selection and contextsourceId

Shared response schemas cover 200, 201, 202, 204, 400, 401, 403, 404, and 409.

The standard problem body uses type, code, title, status, and detail.

Format note: Values such as kebab-case, Timezone IANA name, and <ulid> or string are descriptive hints. OpenAPI tools do not treat them as standard formats.

07 · Security contract

Read and write operations use different declarations

Example read operations

API key

The OpenAPI source declares apiKey. Bruno sends Backendbase-Api-Key.

Protected operations

API key Bearer token

Account operations, Example writes, and greeting delivery declare both schemes. Bruno sends both headers.

Authentication

API key

Bruno sequence 10 calls POST /auth and stores the returned access token for protected lifecycle requests.

security:
  - apiKey: []
    bearerAuth: []

Both keys in one security requirement mean logical AND. Separate list items would mean logical OR.

Runtime alignment: Missing or invalid API keys and bearer tokens return status 401. ACL denials return status 403.

08 · Generate and validate

Build one tool-ready OpenAPI file

The Composer script calls php-openapi inline. It resolves external file references and writes one YAML document.

  1. Edit the root document, shared components, or feature path source.
  2. Generate public/example-api/docs/example-api-merged.yml.
  3. Validate the generated file against the OpenAPI 3.0 schema.
  4. Review the generated difference before commit.
composer run generate-example-api-spec
vendor/bin/php-openapi validate public/example-api/docs/example-api-merged.yml
Important: The generation script does not run validation. Run validation as a separate command.

Development housekeeping and the immutable release artifact builder also generate the specification.

11 · Request structure

Use variables for environment-specific values

The create request shows the full pattern. It reads URL, credential, context, and fixture values from the selected environment.

info:
  name: "Add New Example"
  type: "http"
  seq: 41

http:
  method: "POST"
  url: "{{baseUrl}}/example-types/{{type-slug}}/groups/{{example-group}}/examples"
  headers:
    - name: "Backendbase-Api-Key"
      value: "{{apiKey}}"
    - name: "Authorization"
      value: "Bearer {{accessToken}}"

runtime:
  scripts:
    - type: "tests"
      code: |
        expect(res.status).to.equal(204);

Assertions

Read requests check status and important response fields. Write requests check status.

Authentication

The authentication request captures accessToken for protected lifecycle requests.

The lifecycle generates a run-unique example-key before it creates the example.

15 · Change workflow

Update the contract and executable example together

  1. Define the route, method, path parameters, request body, response, and security rule.
  2. Add or change the operation in resources/api-docs/example-api.
  3. Reuse shared header and response references where they match.
  4. Add or change the Bruno request and its focused assertions.
  5. Implement the route and use case. Add focused PHP tests.
  6. Generate and validate the merged OpenAPI file.
  7. Run the PHPUnit scope. Run Bruno against a clean target.
  8. Review OpenAPI, Bruno, route, middleware, and response payload together.
Done means: One operation has one route, one accurate contract, one executable example, and behavior checks.

16 · Current alignment gaps

Known differences need an explicit owner

Example group queries return the complete distinct-group total and the requested page. Both collection endpoints reject offsets above the signed 64-bit integer range with status 400 before query dispatch.

PriorityAreaCurrent differenceSuggested action
MediumBruno report dataThe report must remain safe to share.Keep credentials and request and response bodies excluded.
MediumRequest bodiesExample creation requires lookupValue. PATCH treats explicit null as omitted, although its schema does not declare those fields nullable.Match schema requirements to boundary validation.
MediumCORSAllowed headers omit Accept-Language.Align CORS with the public header contract.
LowDetail timestampsThe controller emits DATE_ATOM, while OpenAPI uses the nonstandard datetime format.Align the schema with the emitted date-time contract.

These items describe the repository state. They are not changes made by this guide.

18 · Review checklist

Check every public operation change

Contract

  • Method and path match the route.
  • Path and query parameters match runtime input.
  • Required headers match middleware.
  • Body required fields match validation.
  • Response fields and status codes match output.
  • Security requirements match enforcement.

Executable example

  • Bruno uses environment variables.
  • Assertions check status and important fields.
  • Write data has deterministic cleanup.
  • No real secret is stored in the repository.
  • The merged file generates and validates.
  • Focused tests and Bruno pass.
