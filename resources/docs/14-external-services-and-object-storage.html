01 · Overview

Keep vendor details at the infrastructure boundary

Application and domain code must depend on a project-owned port. An infrastructure adapter owns the vendor Software Development Kit (SDK), request mapping, and response mapping.

Port

Defines the capability in project terms.

Adapter

Maps the port to one vendor API.

Composition

Builds the client and adapter in the dependency container.

02 · Integration boundary

Use one owner for each external contract

  1. Use caserequests capability
  2. Project portdefines contract
  3. Adaptermaps values
  4. Vendor clientsends request
  5. Remote APIreturns outcome
  6. Adapterreturns project value

Do not pass vendor request or response objects across the adapter boundary. Translate recoverable vendor errors into stable project exceptions.

03 · Add a service

Start from the required external action

  1. Identify the owning bounded context and exact external action.
  2. Review the official vendor contract and SDK support.
  3. Define a narrow project-owned port.
  4. Implement one adapter under infrastructure code.
  5. Add validated settings and dependency-container wiring.
  6. Test request mapping, response mapping, and failure cases with doubles.
The repository includes an add-external-service skill and workflow reference. They describe the expected vendor-subtree pattern. No populated vendor service subtree exists in the inspected source.

05 · Failure policy

Classify errors before retrying work

Input or contract

Reject invalid data and malformed remote responses.

Transient

Retry timeouts, connection failures, and selected server errors with limits.

Permanent

Do not retry denied, missing, or invalid requests without a state change.

Retry a state-changing request only when the vendor supports idempotency or the project can prove a safe outcome.

06 · Object-storage flow

BucketService isolates AWS S3

  1. Calleruses BucketService
  2. S3Bucketvalidates key
  3. S3 clientsigns or uploads
  4. Bucketstores object
  5. CDN or S3creates access URL
  6. Callerreceives result

The port supports download URLs, local-file uploads, and signed browser-upload forms.

07 · Download URLs

Prefer the configured Content Delivery Network URL

getPreSignedUrl() returns null for an empty key. It returns CDN_BASE_URL + key when a Content Delivery Network (CDN) base URL exists.

Without a CDN, the adapter creates a time-limited S3 GetObject request. The current request sets the response content type to image/jpeg.

08 · Server uploads

Resume multipart uploads after an SDK failure

putFile() opens the local file as a stream and uses ObjectUploader. A multipart failure rewinds the stream and resumes with MultipartUploader and the saved upload state.

The upload loop has no explicit retry limit. Add a bounded policy before using this path for unreliable or untrusted workloads.

09 · Browser uploads

Create a private signed POST for one key prefix

createSignedRequest() rejects an empty key. It returns form attributes and inputs for a private S3 POST.

The method accepts contentType, but the current policy does not use it. A client can submit a different content type unless another control rejects it.

10 · S3 wiring

Settings build the AWS client and project adapter

Environment keySetting
OBJECT_STORE_ACCESS_KEYExplicit S3 access key
OBJECT_STORE_SECRET_KEYExplicit S3 secret
OBJECT_STORE_REGIONAWS region
OBJECT_STORE_ENDPOINTOptional S3-compatible endpoint; uses AWS_ENDPOINT when unset or empty
BUCKET_NAMES3 bucket
CDN_BASE_URLOptional direct delivery base URL

The dependency container creates S3ClientInterface with explicit credentials. A custom endpoint uses path-style requests. SQS and SNS can use the AWS credential provider chain when both credential values are empty.

Run docker compose --profile integration up -d for stateless local S3, SQS, and SNS endpoints. Create each required resource in the integration test setup.

11 · Current gaps

Known integration and storage limits

  • The S3 upload retry loop has no explicit attempt limit.
  • Signed browser uploads do not enforce the supplied content type.
  • Download signing forces an image response content type.
  • S3 always receives an explicit credential object, including empty values.
  • No general external-service adapter exists as a live example.

12 · Tests

Use doubles by default and opt in to emulator tests

vendor/bin/phpunit tests/Infrastructure/Adapters/S3BucketTest.php
vendor/bin/phpunit tests/Shared/Integrations

Use SDK and port doubles in the default suite. Use the integration profile for explicit S3, SQS, or SNS adapter integration tests. Test empty keys, signed expiration, success mapping, malformed responses, timeouts, and exhausted retries.

13 · Checklist

Add an integration safely

  • The owning context and external action are clear.
  • A project-owned port hides vendor types.
  • Configuration validates required values.
  • Network timeouts are finite.
  • Retries are bounded and idempotent.
  • External responses are validated.
  • Secrets and personal data stay out of logs.
  • Tests use deterministic doubles.
